# `coverage.yml`: test coverage

[← Workflows of control-toolbox](../README.md)

Runs the test suite with coverage on `ubuntu-latest` (default Julia of `setup-julia`),
processes it, and uploads it to Codecov. Caller: `Coverage.yml`, in every package. It
runs on pushes to `main` and on tags, never on a PR.

## Caller

```yaml
# .github/workflows/Coverage.yml
name: Coverage

on:
  push:
    branches: [main]
    tags: '*'

jobs:
  call:
    uses: control-toolbox/CTActions/.github/workflows/coverage.yml@main
    with:
      use_ct_registry: true
    secrets:
      codecov-secret: ${{ secrets.CODECOV_TOKEN }}
      SSH_KEY: ${{ secrets.SSH_KEY }}
```

## Inputs and secrets

| Input | Default | Meaning |
| --- | --- | --- |
| `use_ct_registry` | `false` | Add `ct-registry` (needs `SSH_KEY`) |

| Secret | |
| --- | --- |
| `codecov-secret` | Codecov upload token (`CODECOV_TOKEN`) |
| `SSH_KEY` | for `ct-registry` |

The coverage badge is generated by [`update-readme.yml`](update-readme.md) (`Coverage`).

## On a push to `main`: the label `ci on main: changes only`

The first job, `changes`, decides whether the jobs of this workflow run on a push to `main`.
Without the label `ci on main: changes only` on the merged pull request they always run;
with it, they run only if a changed file can affect them. The input `ctactions_ref`
(default `main`) is the ref of CTActions whose scripts `changes` runs, to test a change. See
[CI on `main`](ci-on-main.md).
